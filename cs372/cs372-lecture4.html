PART III: HOW LLM REASONING WORKS

Chain-of-Thought (CoT) Prompting

Generate a sequence of intermediate reasoning steps before the final answer.

Key Insight

Emergent capability at ~100B parameters. Smaller models don't benefit from CoT prompting.

Variants

  • Few-shot: Provide examples with reasoning
  • Zero-shot: "Let's think step by step"

Example

Q: Roger has 5 tennis balls. He buys 2 cans of 3 balls. How many?

A (without CoT): 11

A (with CoT):

Roger starts with 5 balls.

2 cans × 3 balls = 6 balls.

5 + 6 = 11 balls. ✓

Connection to CRIT: CoT makes reasoning explicit, similar to how CRIT requires justification for each argument.

Wei et al., "Chain-of-Thought Prompting Elicits Reasoning in LLMs" (NeurIPS 2022)

''')) # Slide 18: Self-Consistency slides.append(('slide18.html', '''

PART III: HOW LLM REASONING WORKS

Self-Consistency

Sample multiple diverse reasoning paths, then select the most consistent answer via majority voting.

Key Idea

Complex reasoning problems often have multiple valid paths to the correct answer. Consistency across paths signals reliability.

Benefits

  • Reduces variance from greedy decoding
  • Works with any CoT prompt
  • Simple ensemble approach

Process

1. Sample k reasoning paths (high temperature)

2. Extract final answer from each path

3. Take majority vote across answers

Connection to CRIT: Like CRIT's prompt ensemble — same question, different phrasings, vote on answer.

Wang et al., "Self-Consistency Improves Chain of Thought Reasoning" (ICLR 2023)

''')) # Slide 19: Tree of Thoughts slides.append(('slide19.html', '''

PART III: HOW LLM REASONING WORKS

Tree of Thoughts (ToT)

Combines deliberate reasoning with systematic search. The LLM generates, evaluates, and explores thought branches.

Three Key Components

  • Generate: Multiple candidate thoughts per step
  • Evaluate: Self-assess progress toward goal
  • Search: BFS or DFS through thought tree

Best for: Tasks requiring exploration, backtracking, or planning (e.g., Game of 24, crosswords)

ToT vs CoT vs Self-Consistency

Method

None

Best path

Connection to CRIT: ToT's self-evaluation mirrors CRIT's elenchus — validating each reasoning step.

Yao et al., "Tree of Thoughts: Deliberate Problem Solving with Large Language Models" (2023)

PART IV: EVALUATING REASONING QUALITY

ORM vs PRM: Reward Models

Outcome Reward Model (ORM)

  • Evaluates only the final answer
  • Coarse-grained, sparse signal
  • Lower annotation cost
  • May overlook intermediate errors

score = f(final_answer)

Process Reward Model (PRM)

  • Evaluates each reasoning step
  • Fine-grained, dense signal
  • Higher annotation effort
  • Better credit assignment

score = Π f(step_i)

Key Finding (Lightman 2023): "Process supervision trains more reliable reward models than outcome supervision."

''')) # Slide 23: PRM Training Methods slides.append(('slide23.html', '''

PART IV: EVALUATING REASONING QUALITY

Training Process Reward Models

1. Human Annotation

Experts label each step as correct/incorrect. Gold standard but expensive (~$20/hour × many steps).

2. Monte Carlo Estimation

Complete multiple rollouts from each step, estimate correctness from success rate. Scalable but noisy.

3. LLM-as-Judge

Use strong LLM to evaluate each step. Fast and scalable, but may inherit biases.

Evaluation Methods

Best-of-N

Sample N solutions, select highest-scored by PRM

ProcessBench

Evaluate step-level error detection accuracy

Warning: PRMs optimized for Best-of-N may drift toward outcome assessment (Qwen2.5-Math study).

PART IV: EVALUATING REASONING QUALITY

Test-Time Compute Scaling

Paradigm shift: Instead of bigger models (train-time), use more inference compute (test-time) for better reasoning.

Methods

  • Best-of-N with verifier scoring
  • Beam search with step-level rewards
  • Self-verification and refinement loops
  • Extended chain-of-thought generation

Key Metrics

Pass@K

Probability that at least 1 of K samples is correct

CoT-Pass@K

Verifies intermediate steps, not just final answer (Wen 2025)

Insight: Test-time scaling can match or exceed gains from model scaling, at lower cost per query.

PART V: STATE OF THE ART

Reinforcement Learning with Verifiable Rewards

RLVR uses objective verification (code execution, mathematical proofs) instead of learned reward models.

Key Advantages

  • No reward hacking possible
  • Perfect signal for verifiable domains
  • Extends reasoning boundary (not just sampling)
  • Incentivizes correct reasoning early

Verifiable Domains

Math: Check if final answer is numerically correct

Code: Execute and verify output matches expected

Logic: Formal verification of proofs

Connection to CRIT: Like CRIT's source credibility (θ) — verifiable rewards provide ground truth for evaluation.

PART V: STATE OF THE ART

Self-Verification: Can LLMs Check Themselves?

Unified generation and verification in a single model, eliminating the need for separate reward models.

Gnosis Approach

A ~5M parameter verifier head outperforms billion-parameter reward models and even Gemini 2.5 Pro on ProcessBench!

Key Insight

The model learns to identify errors in its own reasoning during the generation process.

Benefits

  • Single model for generate + verify
  • Shared representations
  • No separate RM needed
  • Lower inference cost

Connection to CRIT: The maieutics method — helping the model reveal its own understanding through self-examination.
