
1. How to combine clustering indexing technology and interactive retrieval
   approach? We know that interactive retrieval approach dynamically 
   update the query's weights based on the user's feedback. If the database 
   images are clustered to several groups, how to calculate the objects' 
   similarity.

   There are two ways to deal with weights. 

   One, we can transform the centroids of the clusters to take the user's 
   weights into consideration.

   Two, we can sample a few points in each cluster to compute the
   average "weighted distance" to determine which cluster(s) is the closest.

5. When we implement batch-mode shadowing crawler, does it make any
   sense if we synchronize the collection by "non-uniform policy?"

   Cho and Garcia-Molina's paper show that using the uniform policy
   can keep the pages most fresh. We should stick to the uniform
   policy for now.

6. Is there any difference between the text-base crawler and the 
   picture-base one for "important matrics?"  

   There are two differences:
   a. Picture-based crawling takes up more Internet bandwidth.
      This may annoy some Web sites that would like to reserve
      bandwidth for real customers. To avoid saturating
      a site's bandwidth, we may want to space out out the time
      to visit the same place.
   b. We may want to crawl images by "category," that is, each
      instance of the crawler get images of one kind...  This
      is just a suggestion.

8. Will the K-mean method be better than Clindex algorithm evaluate 
   by the precision?

   Not really... The K-mean method is good only if you know K.
   In a high-dimensional space, it is hard to tell K.

9. After clustering, there might be still a lot of items 
   (e.g. 1,000,000 = images) for each cluster. If we fetch the 
   whole cluster into the main = memory and perform linear 
   search in the matching phase, it might be very
   costly. Is there any other possible solutions ?

   Yes, it will be very costly to perform linear search. We need 
   to discuss and work out another solution to deal with this problem. 
   One possible solution is "Hierarchical Clustering," that is to 
   reclustering the items in the same cluster based another criteria. 
   Another solution is to build traditional index structures (e.g., 
   B-trees, hash tables) in a large cluster.
