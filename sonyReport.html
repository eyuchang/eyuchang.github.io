Summer Project Report

1. Initial goal & Challenges

  • To develop optimized multimedia file-system and demo applications
          Current multimedia file-systems do not use precise knowledge of disk characteristics. Knowledge of disk parameters such as data layout, mapping, seek, rotational and transfer times are critical for optimal performance of real-time applications such as streaming media. Current file-systems typically underestimate system resources in order to guarantee quality of service (QoS).  From our research in low-level placement, scheduling, we know that precise knowledge of disk can improve system performance significantly. We realized that previous work on disk feature extraction (Scsibench) could be used to improve the performance of existing file-systems.

                In order to evaluate the performance of the file-system, we proposed some benchmark applications. They can be listed as:
                    1. Home multimedia server
                    2. Video surveillance system

  • Designing the improved file-system involved the following challenges :
    • Choosing base filesystem:
               Improvements to an existing filesystem was thought to be better than writing the entire filesystem from scratch. Writing an entire filesystem from scratch would require a lot of time. Also, we could leverage micro-optimizations of pre-existing filesystems to create a filesystem that is superior in all respects.
    • Hacking the source:
              The next challenge is to understand the source code for the chosen base filesystem. This is a really tedious task involving a lot of man-hours. The next step is to then integrate our optimizations in  the appropriate places.
    • Finding working linux video and audio players:
              Till recently, there was not sufficient support for hardware video accelerators under linux. So one of the challenges was to scourge for high-performance audio and video players under linux.
2. Previous Work
  • Scsi Disk feature extraction tool ( ref: FAST2002 )
        This paper proposes methods to extract precise disk parameters which are of interest in designing a high performance filesystem. It also evaluates the accuracy of the proposed methods. ( This paper is attached with the report. )
  • Data organization, placement and scheduling for multimedia data ( ref: ICME2001, EDBT2002 )
          This paper proposes high-level MPEG data organization, low-level placement of multimedia data on disk and IO scheduling algorithms. It evaluates these algorithms using the Scsibench tool to a high level of accuracy. ( This paper is attached with the report. )
 

3. Initial Study

        The inital month was mostly spent in writing two papers ( FAST2002 and EDBT2002 : see above). Some experimental studies were performed at this point. These included validating the scheduling and placement methods proposed in EDBT2002.

        After the papers were out of the way, we started to concentrate on the filesystem implementation.  We decided to use linux as the filesystem development platform. Linux is an open source operating system which gave us the flexibility of changing the source code to add our optimizations. There are a number of real-time file-systems developed for the Linux platform. Any of these could serve as a base filesystem for our optimizations. We list some of these below :
 

XFS ( SGI ) Worst-case bit-rate requirement, Delayed Allocation
ReiserFS ( Namesys.com ) Journalled filesystem
Fellini ( Bell Labs ) Worst-case bit-rate requirement
Symphony ( UT Austin ) Server push, create (handle, data_type, options)
JFS ( IBM ) Journalled file-system
MMFS ( SUNY Stony Brook ) Unix API ( addition: mnode / multiple inodes )
Tiger Shark ( IBM )     ----- Unknown ?? ---- 
RT Linux ( Carnegie Mellon , now TimeSys Inc. ) disk_bw_reserve_create (<period>,<start>,<deadline>)

        In summary, most modern FSs handle continuous requirement at the OS level.  However, we don't see too much intelligence at low-level in these file-systems, leaving room for improvement.

        Any multi-media file-server design must consider the following paramters:
                1. Disk track size
                2. Rotational time
                3. IO Bus Bandwidth
                4. Memory Cost
                5. Stream bitrate

        The relationship between these paramters is complex. They must be managed carefully to ensure optimal performance. In order to identify the crucial parameters, we analyzed the cost trends for memory and disk bandwidth. We also noticed the relation of these resources with the stream bitrate. In conclusion, we state that , in the near future, both disk bandwidth and memory are potential bottlenecks. Hence neither can be ignored completely. We also found that the bottleneck parameter is closely related to the bitrates of the multimedia streams supported in the system.

4. Revised Goals

        After performing our initial study, we realized that some of the initial goals need to be revised. We present the revised goals of the summer project below :

        1. Since we could not decide on the base FS, we decided to implement the file-server at user-level. We would design it so that we could easily integrate it with any FS of choice
        2. We realized that in the short-term, rotational delay optimization is not crucial. Hence we would not concentrate on this issue in the first version of the filesystem.
        3. Admission control is crucial to a streaming multimedia server
        4. Concentrate on demo application with user-level optimizations in place.
        5. Implementation of admission control on top of existing filesysytem.

5. Current Status

  • Streaming server ( without admission control ) and client ( integrated with video / audio player )

    • We have implemented streaming multimedia server and client application responsible for client buffering and conection with different media application for multimedia display. We currently support client applications for streaming mpeg2, mpeg1, DivX, OpenDivX, and audio (including mp3). The server is multithreaded and efficiently implemented (without any busy waiting).
  • Admission control algorithm

    • We have started initial work in admission control algorithms that use realistic disk model. Disk is modeled using our disk feature extraction tool. The first implementation in our demo setup is an algorithm running in user space on top of any file system. We assume that file system's placement is mostly sequential for large multimedia files, and that the access is as good or better than random. More details are in Appendix.
  • File System optimization ( for seek and rotation ) user-level modules

    • There are two major FS optimisations. The first is data organization of multimedia data for interactive applications. The second is scheduling algorithms aware of realistic disk model and data organization. Disk is divided into several zones with substantial difference in disk throughput, and optimal data placement will give substantial benefits. For more information about data organization please refer to Data Organization paper in the Appendix. Scheaduling algorithms can benefit from accurate prediction of rotational delay and access time between any two logical blocks. The details of prediction algorithm are in disk feature extraction paper included in Appendix.
  • Key Findings :
    • Sensitivity of scheduling to average request size
    • Accurate access time (including rotational delay) prediction algorithm
    • Disk utilization-Request Size relationship for random access
    • Scheduling and admission-control algorithms for multi-bitrate streaming server

7. Applications of the technology
  • FTP servers, HTTP servers, Streaming servers

    • Implementing disk access time prediction between two requests will substantially improve disk throughput for a large number of small requests. This will improve performance of HTTP and FTP servers. It will also substantially improve performance of the multimedia servers with large number of clients, and subsequently small buffer size per each stream.
  • Streaming to low memory devices and handheld devices

    • Low memory devices cannot afford to use large buffers, and server has to send small packets over the network. If one server is serving large number of clients, disk request sizes will be small, and the server can benefit from disk rotational delay prediction.
  • Interactive TV applications ( home, local-area, surveillance systems etc. )
  • Heterogenous data servers

    • Heterogenous data servers have both large and small disk request sizes, and they can benefit from better disk scheduler that uses disk access time prediction.
