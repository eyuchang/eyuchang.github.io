> > Comments for author(s);  suggestions for improvement, or specific reasons
> > for rejecting.  Please write clearly and use additional pages as needed:
> >
> > This paper presents an approach to automatically learning a k-CNF query
> > based on user feedback.  The approach -- MEGA -- finds feature
> > combinations using a combination of approaches, including an extension of
> > Valiant's algorithm for refining queries, a genetic algorithm for
> > selecting features, a utility-based approach for sampling data, and fuzzy
> > logic for softening query boundaries.  The descriptions of algorithms and
> > other technical details in the paper are often excellent.  In particular,
> > the review of prior work is very good.  It focuses on work that is
> > directly relevant to MEGA, and clearly contrasts those approaches with
> > those discussed in the paper.
> >
> > Unfortunately, several issues remain to be resolved.  First, MEGA will
> > not be practially useful until users are asked to label fewer instances.
> > Second, the current MEGA algorithm will perform poorly when overall
> > frequency of positive instances is low.  Because of this, either the
> > claims about MEGA should be reduced or MEGA should be modified so
> > performance remains high in the face of low positive rates.  Third,
> > additional experiments should be performed to identify the necessary and
> > sufficient components of MEGA.  These issues are discussed in greater
> > detail below, along with other more minor issues.
> >
> > As currently constructed, MEGA requires a user to label an unreasonably
> > large number of instances before finding an accurate query.  The
> > experimental results are discussed in terms of the number of iterations
> > rather than the number of total instances labeled by a user.  In
> > Experiment I, the user would have to examine and label 60 instances
> > before obtaining a correct query.  This number is already prohibitive for
> > most applications, and this number will increase as the concepts become
> > more difficult to learn, as the positive rate decreases (see below), and
> > as a user's error rate increases.  While MEGA learns quickly, it is still
> > not appropriate for interactive retrieval applications.  Either MEGA
> > needs to learn more quickly (perhaps by reducing its search space) or it
> > should be targeted for other applications for which more data exist (for
> > example, persistent filtering applications).
> >
> > MEGA will not perform well when early queries contain no instances that a
> > user labels as positive.  For most concepts, there are a vastly larger
> > number of ways that an instance can be negative than positive (consider
> > the number of ways of not being a picture of a fish).  This problem poses
> > a central challenge for the claims of the paper, that "[MEGA] learns a
> > concept without the need for good seeds" (p. 4).  For this claim to be
> > generally true, it must hold when the proportion of positive instances in
> > the population is quite small.  In such situations, the probability that
> > a random query will contain positive instances is very small and finding
> > such instances would require the user to label an extremely large number
> > of instances.  A low overall positive rate characterizes most document
> > retrieval applications, and I strongly suspect it will be true for most
> > other retrieval tasks.  The experiments do not appear to consider this
> > issue.  The data set described on p. 17, for example, contains 52,000
> > images in only 18 categories.  Regardless of the distribution of
> > instances among these categories, any experiments with these categories
> > will contain tasks with very high positive frequency.
> >
> > MEGA is a complex system, and it is not clear which aspects of the system
> > are necessary or sufficient to achieve similar performance. As a result,
> > the current experiments with MEGA do little to advance our general
> > knowledge of how to construct adaptive query systems.  Is it necessary to
> > use fuzzy logic, genetic algorithms, or k-CNF concepts to achieve similar
> > performance?  One way of examining these questions is to use additional
> > ablation studies that replace one element of the system with a simpler
> > version.  Experiment I appears to be such a study, but only examines only
> > one component of the system and its description does not make clear
> > whether the comparison systems employed only new sampling approaches or
> > both sampling and learning approaches.
> >
> > The paper would be improved by a more balanced discussion of results.  In
> > Experiment I, the description of results does not acknowledge that other
> > systems perform nearly as well as MEGA.  For example, both the B-Random
> > and Aggressive systems achieve nearly the same results (and both perform
> > better after two iterations) in Table 4.  Indeed, MEGA achieves the
> > lowest accuracy of any system on the second iteration.  The choice of
> > three iterations as the cutoff for Figure 5 (and perhaps other figures)
> > particularly benefits MEGA over other systems.
> >
> > The discussion at the bottom of  p. 14 cites model bias and user errors
> > as the two primary sources of noise.  Another common source is the use of
> > "inadequate" attributes.  That is, the attributes in the data set may be
> > inadequate to partition the classes, even though such a set of attributes
> > exists beyond the data set.  Considering this source of noise would
> > improve the paper.
> >
> > All the graphs that show predicates used to identify particular image
> > classes (figures 20 and 21) show remarkable similarity in the group of
> > features and negations used.  It appears that nearly every time that a
> > predicate is used, so is its negation.  Additional explanation of this
> > phenomenon would improve the paper.
> >
> > The paper sometimes refers to individual data instances (documents or
> > images) as "samples" (as in, "...it will use the negative-labeled samples
> > to reduce the set...").  In other cases, "sample" is used to refer to a
> > set of instances drawn from the set of all available instances.  This
> > latter use is far more common and should be preferred.

> >
> > 1. My first reaction to the prominent claim that the
> > algorithms does not require a seed to work and is therefore
> > superior to others is skepticism. While technically true,
> > the authors describe that they show to users the "most
> > discriminating examples" to quickly converge to a good
> > answer. This itself represents in some way a
> > seeding. (See algorithm step 2a.)
> > Conversely, many other algorithms could start with
> > some random seed and move towards the desired results, how
> > fast is a separate question. page 2 second paragraph can
